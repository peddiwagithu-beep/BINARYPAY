API reference

Create keys in your dashboard under API keys. Send the secret key as a Bearer token. Keep it on your server and never put it in a website or app. Secrets are shown once.

Authorization: Bearer hgp_sk_...

A key works only in the environment its server runs in: sandbox keys on a sandbox server, live keys on production. Live keys require verified business details.

Endpoints

POST /api/v1/payments            start an M-PESA STK Push
GET  /api/v1/payments/:id        check a payment
GET  /api/v1/transactions        list payments (?limit=50&offset=0)
GET  /api/v1/balance             pending and settled balances
POST /api/v1/payment-links       create a hosted payment link
GET  /api/v1/payment-links       list your links

Start a payment

Amounts are whole KES. Send an Idempotency-Key header so a retry never charges twice. The response is always pending. A payment becomes succeeded only after Safaricom confirms it, so poll GET /api/v1/payments/:id.

curl -X POST https://YOUR-DOMAIN/api/v1/payments \
  -H "Authorization: Bearer $HGP_SECRET_KEY" \
  -H "Idempotency-Key: order-1001" -H "Content-Type: application/json" \
  -d '{"phone":"0712345678","amount":100,"reference":"order-1001"}'

JavaScript

const r = await fetch("https://YOUR-DOMAIN/api/v1/payments", {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.HGP_SECRET_KEY}`,
             "Idempotency-Key": "order-1001", "Content-Type": "application/json" },

console.log(await r.json()); // { id, status: "pending" }

Webhooks

Add an HTTPS endpoint in your dashboard under Webhooks. You get a signing secret (whsec_...) once. We POST JSON for these events: payment.succeeded, payment.failed, payout.paid, payout.rejected and webhook.test. Respond with any 2xx status within 8 seconds. Failed deliveries retry up to 6 times with growing delays, so the same event can arrive more than once: use the event id to ignore duplicates.

{ "id": "payment.succeeded:<payment id>", "type": "payment.succeeded", "created": "...",
  "data": { "id": "...", "status": "succeeded", "amount_minor": 10000, "currency": "KES",
            "reference": "order-1001", "receipt": "ABC123XYZ" } }

Verify every request. The HGP-Signature header looks like t=1700000000,v1=<hex>. Compute HMAC-SHA256 of t + "." + rawBody with your signing secret, compare in constant time, and reject if the timestamp is more than 5 minutes old. Use the raw request body, not re-serialised JSON.

// Node.js
const crypto = require("crypto");
function verify(raw, header, secret) {
  const [t, v1] = header.split(",").map((p) => p.split("=")[1]);
  const mac = crypto.createHmac("sha256", secret).update(t + "." + raw).digest("hex");
  const ok = mac.length === v1.length && crypto.timingSafeEqual(Buffer.from(mac), Buffer.from(v1));
  return ok && Math.abs(Date.now() / 1000 - Number(t)) < 300;
}
# Python
import hmac, hashlib, time
def verify(raw: bytes, header: str, secret: str) -> bool:
    t, v1 = [p.split("=")[1] for p in header.split(",")]
    mac = hmac.new(secret.encode(), t.encode() + b"." + raw, hashlib.sha256).hexdigest()
    return hmac.compare_digest(mac, v1) and abs(time.time() - int(t)) < 300
// PHP
function verify($raw, $header, $secret) {
  [$t, $v1] = array_map(fn($p) => explode("=", $p)[1], explode(",", $header));
  $mac = hash_hmac("sha256", $t . "." . $raw, $secret);
  return hash_equals($mac, $v1) && abs(time() - (int)$t) < 300;
}

Payouts

Request payouts from the dashboard. Only settled funds can be withdrawn, and your business must have verified details. The amount plus fee is held at request. An administrator sends the money and records the reference, or rejects the request and the held funds are returned. You can read payouts with GET /api/v1/payouts. Starting payouts through the API is intentionally not available.
